> - stopped Android from starting;
> - broke Bluetooth failover;
> - made document edits quadratic and rejected large pastes;
> - reset legitimate streams;
> - let one stranger hold the frame budget;
> - regressed the desktop chat;
> - put messaging rules into the platform runtime and host.

The `apps/host/tests/history-hook/` harness listed below was removed: it was a manual harness with a machine-specific path. Statements below about behaviour the fixes changed describe the branch as published.

This ledger explains the cumulative implementation changes on `codex/security-hardening`, including their reasons, original commits, validation evidence, and remaining limits.

## Security and resource handling

| Change | Why it was made |
| --- | --- |
| Membership authoring uses the causally maximal **valid** operation frontier, traversing invalid ancestry without truncating genuinely wide valid frontiers. | Invalid descendants could hide valid heads and prevent an administrator from revoking members or sealing content. |
| Missing-parent membership operations are capped at 4,096 total and 256 per author. Ready operations bypass unresolved backlog; bulk insertion promotes newly resolvable operations. | Unresolved-operation floods must not prevent valid administrator updates. |
| Routing-signature cache entries bind all signed fields and signature, including flags, scope, uplink and name; only forwarding cost/hops remain mutable. Cache size zero disables caching. | Origin/sequence alone allowed modified signed metadata to reuse an earlier verification. |
| Admission permits are acquired before spawning network work: 64 inbound streams per process and eight per connection. | Opening many streams could previously create unbounded concurrent tasks. |
| Encoded-frame reservations cap concurrent retained frame bytes at 128 MiB per process and per connection. Permits remain held through processing. | Concurrent large frames could otherwise bypass useful memory accounting. This is not a whole-process heap cap. |
| Frames retain a 64-MiB maximum, but reads grow incrementally in 16-KiB chunks instead of allocating the entire declared length immediately. Serialization is measured before writing into a bounded buffer. | Malicious lengths and oversized serialization should fail before expensive allocation. |
| Add five-second header, 30-second I/O inactivity and 60-second inbound-sync deadlines; progress renews inactivity deadlines. | Stalled peers must release resources without rejecting transfers that continue making progress. |
| Synchronization deduplicates requested operation/envelope IDs and measures exact response size before cloning ciphertext, including response overhead. | Duplicate requests amplified allocations before the old size check. |
| Ephemeral plaintext is capped at 4 KiB, with ciphertext/frame checks before decryption. | Typing-style signals did not need ordinary large-message resource limits. |
| Mesh store-and-forward shares admission/reservation policies and gains bounded summaries, offers, answers, reads, writes and acknowledgments. | Mesh streams must not bypass the ordinary network defenses or retain stalled work indefinitely. |
| Invitation proofs are validated before application consent policy runs; unexpected payload debug formatting is removed from errors. | Invalid proofs must not create durable pending state or expose payload details through diagnostics. |
| Automerge changes undergo bounded framing/checksum/type/length/compression inspection before upstream parsing. Expanded serialized changes are limited to 1 MiB. | Small compressed inputs could cause disproportionate expansion or parser failures. |
| Column inspection caps operations at 65,536, logical cells/group entries at 1,048,576, and expanded strings at 1 MiB. | Byte limits alone did not stop logical run-length or group expansion attacks. |
| Changes are validated against declared dependency history, including actor identity/sequence, nonoverlapping causal counters, object ancestry and upstream counter bounds. | Acceptance must not depend on unrelated local history or arrival order. |
| Document changes apply to a temporary candidate; parsing/application panics are contained. Missing-dependency changes remain outside Automerge's internal queue, with bounded batches and progress-based retries. | One malformed deferred change could poison later valid updates or leave partial state. |
| Canonical actor/sequence fork selection and equivocation exclusions are recomputed as valid history changes; local rejected edits rebuild their prior materialization. | Live, restored and differently ordered replicas must converge; rejected local edits must not contaminate future edits. |

## Attachments, identity and durable state

| Change | Why it was made |
| --- | --- |
| Separate authenticated blob membership from application consent. Persist provisional invitation/accept/decline state before exposing writes; reject unsolicited pushes and explicit downloads for pending or hidden requests. | Cryptographic membership alone did not mean the user accepted file storage. Consent must survive restart. |
| Bound provisional/pending invitations to 256 total and 32 per inviter. | Prevent unlimited pending-request state. A full provisional queue can also defer a known contact's new invitation. |
| Ordinary eager pushes use random create-new disposable staging files, cleaned on failure/cancellation while preserving explicit-download resume state. Keeper uploads retain resumable partials. | Failed pushes left junk and collided with intentional download recovery files. |
| Reserve disk capacity across concurrent remote writers, accounting for resume bytes; fail if free space cannot be established. Retain reservations until workers stop and join canceled workers. | Independent writers reused the same free-space snapshot and could overcommit storage. |
| Add Windows free-space inspection and transfer inactivity deadlines. | Enforce the same admission/cleanup policy across supported platforms. |
| Introduce an identity module with a retained profile lease, bounded reads, no-follow/nonregular-file checks, private Unix directories/files, atomic synced writes and no-clobber seed installation. | I/O errors and concurrent opens could silently replace or corrupt identity; unsafe paths weakened private storage. |
| Bind durable identity markers to backend/state/public key; distinguish absent new profiles from corrupt or incomplete established profiles. Load/save network mode strictly and atomically. | Corrupt state must not silently create a new identity or reset security settings. |
| Migrate the exact existing iOS seed through Pending/Committed durable states into a create-only, device-only, nonsynchronizing Keychain record. Verify readback and binding before removing the legacy seed. | Protect the identity secret while preserving identity and crash recovery. Keychain errors never trigger plaintext fallback or replacement generation. |
| Serialize database commits behind a barrier; retain failed batches and sticky errors; add atomic durable key-value batches. | A flush could previously return before an earlier drained batch committed, and failures could discard writes. |
| Reject malformed persisted security state, trailing data and malformed stored records; stop/close resources on startup failure. | Corruption must surface as an error instead of silently resetting consent or leaving background resources alive. |
| Flush during iOS suspension and background-task expiration; end the UIKit task exactly once using its actual invalid-task sentinel. | Improve persistence during lifecycle transitions without claiming unlimited background execution. |
| Make BLE diagnostics opt-in, keep Unix logs private, and redact attachment-open errors. | Reduce exposure of paths and device/application details in ordinary diagnostics. |

## Direct-chat identity and discovery

| Change | Why it was made |
| --- | --- |
| Serialize concurrent Start chat calls; normalize blank titles and reuse an accepted writable direct conversation for the same signing identity. | Repeated starts, double taps and changed addresses must not create new chats. |
| Present eligible independently created two-person spaces under one stable key derived from sorted signing keys and a deterministic canonical space; expose original IDs as aliases. | Either device may have created a chat before synchronization; network path and arrival order cannot define the person. |
| Preserve original spaces and signed messages. Merge heads of causally ordered source histories; aggregate previews, unread, history, search, visibility, receipts and calls. | Preserve both histories and cryptographic provenance without letting clock skew reorder a source's reply before its parent. |
| Resolve reply/edit/delete/react targets to original sources and send through an eligible writable source. Expose available writer capability without inventing administration rights. | Actions must continue to work on old aliases while enforcing original permissions. |
| Exclude pending/arriving requests, hidden/revoked spaces, named/non-direct histories, former groups and former reader membership from direct aggregation. Ignore ciphertext-only keepers when identifying the two people. | Consolidation must not bypass consent or misrepresent historical group privacy. |
| Resolve stored/selected chat IDs through aliases; key UI history by stable thread identity and preserve loaded messages/hasMore across canonical changes. Reject stale responses after logical thread changes. | Avoid blanking an open chat, losing pagination or leaking the previous conversation's history during consolidation. Exact-ID event filtering still needs later repair. |
| Project call conversation IDs onto logical chats while retaining the original wire state. | A call received through an old alias must open the current conversation. |
| Prefer authenticated signed profile names over imported cards; treat unsigned radio names as fallback. Propagate profile events to contacts, Nearby, network and chats. | Old imported names should not override authenticated renames. |
| Track causal profile IDs separately from timestamp high-water. | A legitimate rename after wall-clock rollback must remain current; stale snapshots must not restore old names. |
| Include directly discovered LAN, Bluetooth and peer-Wi-Fi peers in Nearby. Keep mesh-only routes and recent exchanges separate from physical-proximity evidence. | Non-LAN discoveries were omitted, while other evidence could imply proximity incorrectly. |
| Track raw LAN and native Bonjour discovery sources independently; expire recent-exchange reachability with a one-time status event. | Losing one discovery source must not hide a peer still visible through another, and dead routes must not stay online indefinitely. |
| Add Apple native Bonjour browse/register/resolve/address lookup alongside raw discovery with the existing `_mycel._udp` schema and legacy-compatible base32 identity name. | Handle IPv4/IPv6, multiple interfaces, removals, per-identity address merging, retries and DNS service ownership cleanup. Bound services to 128, IPs/service to 16 and channels to 1,024; resynchronize on callback overflow and retry backpressured transitions. | Avoid stale addresses, lost expiry transitions, leaks and unbounded native discovery state. |

| Change | Why it was made |

### Remaining limits and unimplemented work

- No APNs/PushKit path exists. New message arrival while iOS suspends/terminates the P2P process is not guaranteed. Background receipt was not proved by the recorded foreground catch-up tests.
- Exact Bluetooth → Mac → Wi-Fi physical routing was masked by an alternative USB/shared-network path. First-phone notification checks, fresh request/invite alerts and expanded-video notification navigation need physical coverage.
- Native Bonjour discovery is bounded; this branch does not establish 10,000-user venue capacity. Lists/history/search are not virtualized or cursor-indexed.
- The later audit identified draft loss/send races, edit-draft restoration issues, whole-chat read advancement, incomplete alias event normalization and silent event-gap handling. The proposed normalized store, durable drafts/outbox and new navigation have not been implemented.
- Current forwarding targets one existing eligible chat; new-conversation selection still adds selected nearby people as contacts. Four-tab navigation, a unified recipient picker, durable call history and verified multi-device linking are future work.
- Security hardening preserves the existing encryption protocol. It does not add Signal-style per-message forward secrecy or post-compromise recovery, anonymity, application database/cache encryption, biometric locking, backup exclusions or app-switcher redaction.
- Other platforms retain file-backed identity storage. Accepted-member history/attachment cumulative storage quotas and a whole-process memory cap are not provided. Abrupt process death can leave eager staging files.
- The recorded dependency review found an unresolved `glib 0.18.5` unsoundness advisory and three unmaintained-package advisories. `cargo audit --deny unsound` remains a failing gate; no exception was added. Historical npm audit reported zero vulnerabilities and is not a fresh advisory scan.
- Linux/Windows/Android runtime behavior, sustained fuzzing, physical compromise and independent cryptographic certification were not established by these checks.
